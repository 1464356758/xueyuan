# HARD｜发文、审核、章节与作品管理

## 1. 现行产品状态
番茄在2026-05发布“长篇网文发文规则（第二版）上线通知”，并持续优化长篇审核问题透传。由于具体字段/阈值可能在创作中心动态变化，本学院只保存稳定执行原则，不凭旧截图硬写实时数值。

## 2. 发布前必须通过的系统检查
- 标题、简介、章节名和正文之间不能存在明显虚假承诺；
- 正文不得含系统提示词、AI工作指令、审核记录、GitHub路径、SHA、JSON等生产痕迹；
- 章节顺序必须连续，不能把返修稿、重复章节、草稿说明误发为正文；
- 章节内不得残留“待补”“这里写高潮”“TODO”等占位符；
- 角色名、时间、地点、能力名称必须与项目Canon一致；
- 章节字数满足本项目任务要求，但不得靠水化达标。

## 3. 风险提示
番茄此前上线长篇章节“风险提示”功能。内部处理原则：风险提示只能作为作者复核信号，不等于“未提示就一定合规”。系统仍要执行自己的内容审核。

## 4. 修改与调序
平台具有作品管理、章节管理、调序等产品能力。小说自动化系统不得频繁对已发布内容做大规模无记录重写。若必须修订：
1. 在GitHub保留旧LOCK和新修订版本；
2. 记录修订原因；
3. 检查后续章节引用是否受影响；
4. 再执行平台侧修改。

## 5. 更新稳定性
当前新书榜公开规则含“未断更”等条件。稳定更新是运营要素，但质量优先级不能被机械日更绑架。系统应提前准备可发布缓冲，不通过审核的章节不得因更新压力直接上线。

## 6. 发布与LOCK分离
GitHub中的LOCK只表示小说生产系统内部定稿，不等于已在番茄发布。平台发布状态必须单独记录，防止系统把“内部已锁”误判为“读者已看到”。
